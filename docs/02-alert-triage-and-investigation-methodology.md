# 02 · Alert Triage & Investigation Methodology

This methodology defines a consistent process for reviewing security alerts, investigating suspicious activity and determining appropriate response actions across the simulated SOC environment.

## Process

1. **Review alerts**: examine alerts generated by Elastic SIEM, Splunk and Wazuh.
2. **Validate detections**: determine whether the alert represents genuine suspicious activity or a false positive.
3. **Identify affected assets**: establish the affected endpoints, accounts and relevant indicators.
4. **Collect evidence**: review Windows Event Logs, Sysmon, Linux authentication logs and available network telemetry.
5. **Correlate events**: connect related events across available data sources to establish what happened.
6. **Assess severity**: evaluate the potential impact and scope of the activity.
7. **Determine response**: identify appropriate escalation, containment and remediation actions.
8. **Document findings**: record investigation evidence, decisions and verified outcomes in the investigation register.

## Alert Classification

| Classification | Description | Expected action |
|---|---|---|
| Informational | Activity requiring awareness but no immediate investigation | Record or monitor |
| Low | Suspicious activity with limited indicators of impact | Review and document |
| Medium | Credible suspicious activity requiring further investigation | Investigate and escalate where necessary |
| High | Strong indicators of compromise or significant security impact | Prioritise investigation and containment |
| Critical | Confirmed or suspected severe incident affecting critical systems or data | Immediate escalation and response |

## Investigation Evidence

| Evidence source | Purpose |
|---|---|
| Windows Security Events | Investigate authentication and account activity |
| Sysmon | Examine process execution, network connections and system changes |
| Linux authentication logs | Investigate SSH and other authentication activity |
| SIEM alerts | Review detection details, timestamps and affected assets |
| Wireshark / PCAP | Analyse network flows, packet details, protocols and suspicious communications |
| Threat intelligence | Enrich indicators and assess known malicious activity |
| Endpoint telemetry | Examine suspicious activity and verify response actions |

## Investigation Outcomes

- **True Positive**: the alert represents genuine suspicious or malicious activity.
- **False Positive**: the alert was triggered by benign activity.
- **Inconclusive**: available evidence is insufficient to determine whether the activity is malicious.
- **Escalated**: the investigation requires further analysis or higher-level response.

## Response Options

- **Contain**: isolate affected endpoints or block malicious network indicators where authorised.
- **Remediate**: remove identified threats and address compromised accounts or affected systems.
- **Recover**: restore affected systems and verify normal operation.
- **Monitor**: continue observing activity when immediate containment is not justified.
- **Escalate**: refer incidents requiring additional authority or investigation.

## Limitations

Investigation conclusions depend on the telemetry collected, detection coverage and evidence available at the time. Alert classifications and response decisions must be supported by verified findings rather than assumptions.
